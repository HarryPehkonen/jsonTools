# GLM-5.3 code review — jsonTools (2026-08-28)

External review by z-ai/glm-5.3 (via Hermes proxy), prompted with the shared
core (args, common, errors, paths) plus jtSet, jtMove, jtGet, jtFilter,
jtSort. The model produced 100+ observations and distilled them into this
ranked list. Reproduced here as the working issue list for the fix pass.

## Top correctness/behavioral issues

1. **`require_parent` contract mismatch** — the header promises a container
   check, but it only checks existence: a scalar parent passes, an array
   parent passes without index-range validation. Real gap.
2. **`create_object_path` refuses to descend into arrays entirely** — if
   `set()` calls it unconditionally under `-p`, then `-p` breaks setting into
   existing array elements; even if conditional, the error hint conflates
   "array exists (append)" vs "array missing", and the hint's example command
   can't succeed in the create case.
3. **Error conflation from `find() == nullptr`** — three distinct situations
   (missing key, index out of range, tunneling through a scalar) all surface
   as "path not found". This undermines the project's headline feature (error
   quality). `suggest_for` already walks segments, so `require_at` could
   classify precisely.
4. **No `--` end-of-options** — flag-looking values are unrepresentable:
   `jtSet /cmd --help` triggers help; `jtSet /x --pretty` silently eats the
   value. Unknown flags silently become positionals in most tools (only
   jtFilter reports "unexpected argument").
5. **jtSort doesn't validate non-empty keys** (jtFilter does) — bare `jtSort`
   either depends on unshown sort() behavior or silently does something.
6. **Transitive-include fragility** — jt_get.cpp, jt_filter.cpp, jt_sort.cpp
   use `jt::fail`/`jt::run_cli` without including jt/errors.hpp / common.hpp.
7. **`nearest_key` doesn't escape the suggested key** — paths.cpp's
   `suggest_for` DOES escape (`~`, `/`); inconsistent. Bug if keys contain
   `~` or `/`.
8. **`option_number`** — use `std::from_chars` (C++17) instead of stoll +
   exceptions; the out_of_range message is misleading.
9. **`fail` duplicates `Error::format`** — DRY.
10. **Two Args structs** — common.hpp's `Args` appears vestigial.
11. **Levenshtein threshold fixed at ≤2 regardless of length**; ties resolved
    by iteration order.
12. **Empty-string path accepted as root at CLI** (`jtSet "" 5` replaces the
    whole document) — shell-quoting footgun; consider rejecting empty
    positional args in the mains.
13. **No stdout write-error checking**; `read_stdin` doesn't check stream
    state after read.
14. **Help is one line**; flags undocumented in-tool.

## Library-contract wart

`create_object_path` mutates the document as it walks; on a mid-way throw the
document is partially modified. Masked in the CLI (process exits on error)
but a contract wart if `libjt_core.a` is consumed in-process: document the
exception guarantee (none vs strong) for library verbs.

## Notes for the fix pass

- Fixes must preserve: strict RFC 6901 paths, the `Error at <path>:
  <problem>. <suggestion>` format, exit-non-zero-on-error, no silent coercion.
- Update REQUIREMENTS.md / TECHNICAL_DETAILS.md wherever a fix changes
  observable semantics; README examples must stay verified.
- Build: `cmake -S . -B build -DJT_BUILD_TESTS=ON && cmake --build build -j`
  then `./build/jt_tests` and `./smoke.sh`.
