## HARD RULES

1. **Strict TDD** (test-driven-development skill): write the failing test,
   watch it fail, write minimal code, watch it pass. Never write
   implementation before its test. Vertical slices — one verb at a time, not
   "all tests then all code."

2. **Library-first** (TECHNICAL_DETAILS.md §8): the verb's logic lives in a
   `jt::` function in `include/jt/<name>.hpp` (header-only is fine) or
   `src/<name>.cpp`. The CLI `main()` is ONLY: parse args → call the function
   → write output. No mutation logic in `main()`.

3. **Throw, don't exit** (TECHNICAL_DETAILS.md §8.2): library functions throw
   `jt::Error` (carrying `path`, `problem`, `suggestion`). The CLI shim catches
   `jt::Error` and calls `jt::fail()` (which formats `Error at <path>:
   <problem>. <suggestion>` and exits 1). Never call `exit()` or `jt::fail()`
   from library code.

4. **Strict JSON Pointer** (REQUIREMENTS.md §4): paths are RFC 6901. Whole-doc
   verbs take leading-slash absolute pointers; `jtSort`/`jtFilter` take
   element-relative key paths with NO leading slash. Do NOT invent `./name` or
   any non-standard syntax.

5. **Values are literals or explicit paths only** (REQUIREMENTS.md §7). JSON
   literals are parsed with JSOM's `parse_document` — never treated as bare
   strings. No shell, no env, no code evaluation.

6. **Strict typing** — no silent numeric/string coercion (REQUIREMENTS.md §7).

## Per-verb acceptance criteria (behavior — see docs for full detail)

- **jtFrom** `<file> [--check-only] [--max-depth N] [--max-size N] [--warn-duplicates]`
  reads + validates a file before emitting; `--check-only` emits nothing.
- **jtSet** `<path> <literal> [-p]` sets a literal; error on missing
  intermediate unless `-p` (which creates objects only, never arrays); `-`
  append sentinel works via JSOM `set_at` (JSOM already supports it).
- **jtMove** / **jtCopy** `<from> <to> [--if-not-set|--replace]` — default
  overwrite; `--if-not-set` only-if-absent; `--replace` only-if-exists;
  move removes source; move-into-own-child is an error.
- **jtRemove** `<path>` — delete; missing → error with nearest-key hint.
- **jtGet** `<path> [--default <literal>]` — emit value; missing → default or
  error. `jtGet /` is identity (allowed).
- **jtSelect** `<path> [<path>...]` — flatten to leaf keys; duplicate leaf =
  error; zero paths = error.
- **jtZip** `<keysPath> <valuesPath>` — build object; length mismatch = error;
  key collision = error unless `--overwrite` (last-wins).
- **jtSort** `[<listPath>] <key> [--desc-for <key>]...` — stable multi-key;
  `--desc-for` = next single key only; no keys = natural-type sort (mixed =
  error).
- **jtFilter** `[<listPath>] <keyPath> --op <literal>` — keep matching
  elements; `--op` ∈ eq/ne/gt/ge/lt/le; missing key = dropped silently.
- **jtLen** `<listPath> <destPath>` — write length to dest leaf (create leaf).
- **jtType** `[path]` — emit type string.
- **jtKeys** `[path]` — emit keys array.

## Error model (REQUIREMENTS.md §6)

Every failure formats as: `Error at <path>: <problem>. <suggestion>` to stderr,
exit code 1, nothing on stdout. Use `jt::fail()`. Include a Levenshtein
"did you mean /real/key?" suggestion where a lookup misses (there's a
`nearest_key` helper mentioned in TECHNICAL_DETAILS.md §2.2 — implement it in
the shared core if not present).
