## Remaining verbs to implement (all 9)

    jtRemove  jtGet  jtSelect  jtZip  jtSort  jtFilter  jtLen  jtType  jtKeys

Semantics are in REQUIREMENTS.md §5 (and §12 for jtType/jtKeys) and
TECHNICAL_DETAILS.md §3.5–§3.11. Read them. Highlights:

- **jtRemove** `<path>` — delete; missing → error + nearest-key hint.
- **jtGet** `<path> [--default <literal>]` — emit value; missing → default
  (JSON literal) or error; `/` = identity (allowed).
- **jtSelect** `<path>...` — flatten to leaf keys; dup leaf = error; zero
  paths = error.
- **jtZip** `<keysPath> <valuesPath>` — build object; length mismatch =
  error; key collision = error unless `--overwrite` (last-wins).
- **jtSort** `[<listPath>] <key> [--desc-for <key>]...` — stable multi-key;
  `--desc-for` = next single key only; no keys = natural-type sort (mixed
  types = error).
- **jtFilter** `[<listPath>] <keyPath> --op <literal>` — keep matches; ops
  eq/ne/gt/ge/lt/le; missing key = dropped silently; keyPath relative
  (no leading slash).
- **jtLen** `<listPath> <destPath>` — write length to dest leaf (CREATE leaf).
- **jtType** `[path]` — emit type string ("object"/"array"/"string"/...).
- **jtKeys** `[path]` — emit array of object keys.
